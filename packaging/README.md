# Packaging and distribution

Everything here is drafted in Phase 6. Nothing is published by the project
maintainers without an explicit release decision.

## Planned artifacts

| Channel | Artifact | Tool |
| --- | --- | --- |
| Windows CLI | `cockpit-x86_64-pc-windows-msvc.zip` + PowerShell installer | cargo-dist |
| macOS CLI | universal or per-arch tarball + shell installer | cargo-dist |
| Linux CLI | `x86_64-unknown-linux-gnu` tarball + shell installer | cargo-dist |
| Homebrew | formula generated by cargo-dist | cargo-dist |
| npm | `npx cockpit` wrapper that downloads the matching binary | npm package |
| winget | manifest draft | winget-pkgs |
| scoop | manifest draft | scoop bucket |
| Windows app | MSI and NSIS bundles | Tauri 2 |
| macOS app | `.dmg` | Tauri 2 |
| Linux app | AppImage and `.deb` | Tauri 2 |
| Android | signed APK | Tauri 2 + Gradle |

## Rules

- No background update pings. The app contacts GitHub Releases only when the
  user presses `Check for updates`.
- Release binaries are built from a tagged commit in CI, never from a developer
  machine.
- Android signing keys are supplied by the user and never committed.
- Checksums are published next to every artifact.
- The npm wrapper verifies the downloaded binary's checksum before running it.

## Android signing (drafted, not yet active)

```powershell
keytool -genkeypair -v -keystore cockpit-release.keystore `
  -alias cockpit -keyalg RSA -keysize 2048 -validity 10000
```

Set `COCKPIT_ANDROID_KEYSTORE`, `COCKPIT_ANDROID_KEYSTORE_PASSWORD`,
`COCKPIT_ANDROID_KEY_ALIAS`, and `COCKPIT_ANDROID_KEY_PASSWORD` in the release
environment. Never commit the keystore or passwords.
